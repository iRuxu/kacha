# 项目工作约定

## 制作临时文件

AI 生成的用途或归属尚未明确的临时文件放在 `.kacha/tmp/`，可按任务建子目录。咔嚓工作台自身的缓存、运行状态和临时文件放在 `.kacha/` 下，整个目录由 Git 忽略。

能对应到具体角色、场景、道具或分镜的制作资料，从生成时起就按该对象的目录约定存放。生图、修图的实际提示词、参考图顺序和版本记录随对应资产或分镜保存；改版前的旧图、旧提示词按原有规则在所属目录的 `archive/` 归档。

## 项目设定

读取和更新设定时，世界观及人物、地点、物件之间的关系归入 `docs/story/`，视觉风格与生成要求归入 `docs/art/`，其余项目设定归入 `docs/other/`。

### 全剧画幅

- 在 `docs/other/补充说明.md` 的「全剧画幅」中记录全剧采用的方向和宽高比，例如「横屏 16:9」或「竖屏 9:16」。用户确定或调整全剧画幅时，更新此处。模板中的示例仅供填写。
- 规划分镜前读取全剧画幅，据此安排人物站位、取景和构图。生成关键帧、设置视频画布和导出成片时沿用同一比例，交付时用文件的实际宽高核对。角色三视图、道具参考图等资产按各自用途确定比例。
- 若画幅仍为「待填写」，先查用户本次要求和已有项目设定；仍无法确定时，在制作依赖画幅的画面前向用户确认。若用户只指定某个镜头或交付版本采用其他画幅，在对应分镜或版本说明中记录其适用范围。

## 选择制作技能

接到制作任务时，先在项目的 `node_modules/@2kog/kacha/skills/` 查看技能目录，根据各 `<技能名>/SKILL.md` 的 `description` 选择匹配的技能，再读取完整说明。项目有专属约定时，以本项目的说明为准。

使用全局安装时，通过 `npm root -g` 找到全局模块目录，再读取其中的 `@2kog/kacha/skills/`。

## 剧本、成片与分镜

- 每集使用 `scripts/<三位编号>-<集名>-<标题>/`，编号从 `001` 开始。片头和片尾分别使用 `scripts/opening/` 和 `scripts/ending/`。
- 每个目录建立 `index.md` 和 `archive/`。`index.md` 是默认剧本，其他 Markdown 文档可按需放在同级。修订默认剧本前，将上一版完整稿保存到 `archive/vNNN.md`，从 `v001.md` 起按目录递增。
- 最终成片放在 `dist/scripts/<剧集>/`，剧集目录与剧本一致。默认成片命名为 `index.<扩展名>`，多个交付版本可用 `index-<版本标识>.<扩展名>` 并存，例如 `index-4k.mov` 和 `index-8k.mp4`。扩展名保留文件的实际格式。与成片配套的字幕放在同目录，按对应成片的基本文件名命名，例如 `index.srt` 或 `index-4k.srt`。
- 整理已有项目时，先核对文件实际位置、所属剧集、采用状态与现行引用，再移动和命名。已有用户命名或项目约定时按本项目约定处理，避免覆盖同名文件。移动后更新现行链接，保留历史记录的原文。

### 分镜目录与交付

最小分镜组（未分段的场次或已分段的段落）的视频片段统一放在 `dist/storyboard/<剧集>/<场次>/[段落]/`，镜像对应关键帧目录的相对路径。每组可保留一个或多个视频。默认片段命名为 `index.<扩展名>`，其他片段使用可区分的文件名，保留实际视频格式。

1. `storyboard/` 的一级目录与 `scripts/` 的对应目录同名。分集沿用完整的 `001-集名-标题/`，片头用 `opening/`，片尾用 `ending/`。
2. 分集内按剧本场序建立 `001-场名/`、`002-场名/`。未分段的场次直接存放关键帧。长场按剧情需要在场次下建立 `001-段名/`、`002-段名/`，各段的关键帧和对应词稿放在该段目录。段名直接写内容，如 `001-入场/`。正式分镜目录最多到段落或镜头这一级。
3. 关键帧命名为 `001-画面描述.png`。每场从 `001` 开始按叙事顺序编号，同场跨段连续。跨段复用图片时，引用其所属目录的现行文件。
4. 每组关键帧同目录维护三份文档。`分镜.md` 保存本组原始镜头规划；`生图.md` 按现行图片文件名逐张登记实际生成或最后一次修图的提示词原文、附图顺序与用途、渠道及已知参数；`即梦.md` 保存本组镜头的即梦视频提示词。复用图片注明来源。可以链接到能逐图定位的原始记录，无法核实原词的图片标记「原始生成词缺失」。
5. 创建关键帧目录时同时建立 `archive/`。修订前，将本次涉及的旧版词稿和对应关键帧放入该 `archive/` 的同一个版本子目录，现行文件保留在关键帧目录。
6. 工作台分镜展示只纳入正式编号的场次、段落和镜头。遍历时跳过未编号的辅助目录及其全部内容，例如 `特写/`、`逐人落座/` 和 `archive/`。保留这些目录里的素材；顶层 `opening/`、`ending/` 是正式入口。

### 分镜制作流程

按用户本次要求推进到相应阶段。镜头按剪辑需要设计，关键帧按画面变化准备，视频生成任务按连续表演和渠道能力组织。一个镜头可以用两张关键帧约束动作起止，一次视频生成也可以包含多个自然切换的镜头。

1. **先读剧本、项目设定和现行资产。** 读用户指定版本或本集现行剧本，核对本场原对白、开场状态、剧情变化和前后场衔接。再查看项目实际的 `docs/` 目录，按本场内容阅读以下设定，包括项目自行增加的文档。
   - `docs/story/`：从《世界观与角色》核对人物关系、动机、时间线和世界规则，据此安排谁在场、谁说话、谁作出反应。
   - `docs/art/`：先读已有的全剧视觉风格与生成规范，再读《角色美术》《场景与空间》《道具美术》中涉及本场的内容。把造型、服装、出入口、光源、固定陈设及道具状态落实到具体镜头。
   - `docs/other/`：先从 `docs/other/补充说明.md` 的「全剧画幅」读取画面比例和横竖方向，用于分镜构图、关键帧和成片，再查看与本场相关的专项约定，例如声音、称谓或交付要求。
   - 对照本场已有分镜和相关资产的 `README.md`、`index.json`，实际打开将使用的现行参考图。保留用户已经选定的动作、表演、构图和节奏；只修一镜时，核对该镜及受影响的前后衔接。

2. **先写 `分镜.md`。** 按播放顺序写清镜号、叙事作用、景别与机位、动作与表情、原对白、声音和剪接点。原对白逐字保留，按自然语速和动作需要估算时长。长场按完整对话、连续动作、时空变化或剧情转折分段。例如听者的反应镜头可以承接说话者的画外音，翻页或合账则要交代动作如何完成。

3. **制作关键帧，同步记录 `生图.md`。** 按项目画风、画幅及用户指定渠道制作。实际附上选定的参考图，写明各图分别约束人物身份、服装、空间、光线、道具或指定机位。每张关键帧独立成图；正反打、大幅换景别、改变观察方向或关键动作起止缺少画面依据时，补相应关键帧。轻微推拉或同一构图内的小幅表演可以交给视频完成。图片落盘后，按实际文件名登记本次输入、附图顺序与用途、渠道和已知参数。

4. **逐张检查，再按播放顺序连看。** 核对文件实际像素与画幅、角色身份和比例、服装配饰、道具状态及动作是否清楚。跨镜重点检查人物左右与视线、建筑朝向、光线、背景动态和动作承接。例如人物已经接过信封，下一镜应从持有信封的状态开始。局部修订保留已认可部分，按上节规则归档旧图与旧词。分别记录生成、检查及用户认可情况，认可范围具体到对应画面。

5. **根据当前关键帧编写 `即梦.md`。** 每个生成段提供一份可独立复制的完整指令，按下节格式先交代时长、风格和本段资产，再在对应时间段关联关键帧。正文用连续时间段写出景别、运镜、动作表情、原对白、必要声音及结尾状态；最后一个区间结束于本段总时长。用动作、视线、声音或明确剪接承接下一段。已确定的关键帧全部对应到提示词；渠道的时长或附图数量有限时，先调整分段，确需取舍则说明原因。交付或修订视频提示词时，在聊天里一并给出完整可复制稿。实际提交视频生成按用户本次授权执行。

### 即梦提示词格式

每个生成段在 `即梦.md` 中提供一份可独立复制的提示词，依次写以下内容。

1. **生成指令。** 首句写“生成一段〈时长〉秒〈本剧风格〉短剧”。时长取本段实际安排，风格取项目 `docs/` 中现行的美术设定；用户明确指定本段特殊风格时，采用指定风格。
2. **本段资产。** 编写「涉及角色」「涉及道具」「涉及场景」前，逐项核对对应资产库。只列本段实际使用且已独立建档的资产，名称照录该资产 `index.json` 的 `name`，供即梦圈选。某类没有符合条件的资产时，省略整行。未独立建档的群众、随身物件、服装配件和场景陈设，仅在镜头正文按表演或连续性需要描述。
3. **环境交代。** 用简短的一段话建立本段共用的时间、空间、光线与氛围。
4. **分时镜头。** 每个时间段另起一段，以“0–3秒，〈景别或机位〉，参考图1。”这样的句式，将关键帧圈选放在对应镜头旁。图号按本次上传顺序，在文档中注明与实际文件名的对应关系，可将上传对照放在可复制正文之外。随后写运镜、动作、表情、逐字原对白、声音或剪接。时间连续，最后一个区间结束于首句声明的总时长。
5. **全段共用要求。** 按实际需要补充跨镜持续的背景动态、道具状态、对白语言、环境声和配乐要求。每段可独立复制的即梦视频提示词，正文最后一句必须单独写「不要加字幕。」

## 存放与更新资产

开始制作或整理前，核对资产的实际目录、现行索引、用户说明和当前引用。沿用现有分组与路径，尊重用户移动、改名和删除素材的操作。业务目录中的说明由项目维护，记录该资产的设定、用途、连续性和已确认版本。

### 分组、登记与采用

- 每项资产一个目录，根部维护 `index.json` 和 `README.md`。索引字段 `name` 为名称，`tags` 为自定义标签数组，`note` 为用户备注。素材路径相对于该资产目录，保留文件实际格式。
- 五类资产库都允许多层分组。新建分组时每层放内容为 `{}` 的 `group.json`，具体资产以根部的 `index.json` 标识。使用相对资产库根目录的完整路径区分同名资产。分组名自动成为标签，隐藏的继承标签记入 `hiddenGroupTags`。
- 新稿按用途另存。采用状态依据用户确认和资产说明填写，`candidate` 为候选，`adopted` 为已采用，`reference` 为参考。选择封面只影响展示。缺失素材保留缺项。
- 生成词只登记能与当前文件核实对应的实际输入。保留原始生成记录中的提示词、附图顺序和已知参数。发生改名或移动时，更新现行索引、说明和分镜引用，历史记录保留执行时的原文。

### 角色 · `assets/characters/`

- 新建角色时建立 `index.json`、`README.md`、`portraits/`、`skin/`、`voice/` 和 `archive/`。角色说明记录已确定的背景、外观、固定配饰、现行素材和待补项。
- 默认二维和三维三视图分别用 `2d-turnaround.<扩展名>`、`3d-turnaround.<扩展名>`，路径登记在 `image2d`、`image3d`。封面 `mainImage` 选其中一个字段名。单张立绘、探索稿按实际用途另存。独立三维模型使用单文件 GLB，路径登记在 `model3d`。
- 表情、角度和配饰特写放入 `portraits/`，可再分组。服装和造型变体直接平铺在 `skin/`，文件名区分造型、视角及 2D 或 3D 版本。
- 默认音色使用 `voice/index.<扩展名>` 并登记在 `voice` 字段。其他音色样本和角色台词放在同一目录，使用描述性文件名。
- 默认图、模型和默认音色的实际生成词存入 `prompts`，以相应索引字段名为键。特写与皮肤使用 `assetPrompts`，以文件相对于角色目录的路径为键，移动文件时同步更新键。

### 场景、道具与其他图片的共同索引

根目录用一份 `index.<扩展名>` 作为现行主图。每张图片在 `images` 中登记 `id`、`file`、`label`、`category` 和已知的 `status`。`mainImage` 指向主图条目的 ID。替换同一条目时沿用其 ID。生成词直接写入条目的 `prompt`，或用 `promptRecord` 引用资产目录内的原始 JSON，必要时用 `promptEntry` 定位其中的条目。

### 场景 · `assets/scenes/`

同一地点的机位与环境变体共用一个资产目录。需要独立维护空间连续性的地点可拆分，多个房间共用的外景或定位图保留一份并相互引用。选能说明空间关系的画面作主图。场景说明集中在资产根部的 `README.md`，记录位置、通路、朝向、固定陈设和跨机位连续性。

| 素材 | 目录 | `category` |
| --- | --- | --- |
| 机位 | `views/` | `view` |
| 时间 | `time/` | `time` |
| 天气 | `weather/` | `weather` |
| 季节 | `seasons/` | `season` |
| 空间定位 | `layout/` | `layout` |
| 局部与陈设 | `details/` | `detail` |

按需创建目录。一张图涉及多种环境条件时，在条目的 `conditions` 中按实际情况填写 `season`、`time`、`weather`。

### 道具 · `assets/props/`

同一道具的角度、状态与交付版共用一个资产目录。正侧背等角度图放 `angles/`，分类为 `angle`。细节、开合或亮灭状态及其他交付参考放 `portraits/`，分类为 `portrait`。道具说明记录剧情用途、材质、相对尺寸、握持方式和跨机位需要保持的细节。

### 其他素材 · `assets/other/`

字标、地名标识、后期叠加图形、特效和交付素材按项管理。扩展图放 `extend/`，按用途使用分类 `graphic`、`effect` 或 `delivery`。

### 可复用音频 · `assets/audio/`

音乐、音效和可复用台词按项建立目录，环境底声归音效。音频文件放 `tracks/`，索引的 `tracks` 数组登记 `id`、`file`、`label` 和 `category`，`mainTrack` 指向主音轨 ID。资产的 `type` 和音轨的 `category` 可取 `music`、`effect`、`dialogue`。用途写在资产的 `note`，音轨来源与授权写在 `source`，可循环时标记 `loop`。角色音色随角色保存。

### 替换与归档

- 首次补缺直接写入现行目录。替换现行素材、修订已有生成词或改写资产说明前，将上一版保存在该资产的 `archive/YYYY-MM-DD-vNNN/`。版本号在该资产内递增，一次修订共用一个版本。修改说明时保存旧 `README.md`。
- 角色归档保存旧 `index.json` 和本次被替换的文件，包括对应的旧生成词。特写和皮肤旧图放在版本目录根部，旧词保留在归档索引的 `assetPrompts`。现行 `history` 追加 `version`、`changes` 和 ISO 8601 格式的 `archivedAt`。
- 场景、道具和其他图片归档用版本目录内的 `index.json` 的 `images` 登记旧图及对应生成词。现行索引更新图片条目，在 `history` 追加 `version`、`note` 和 ISO 8601 格式的 `archivedAt`。
