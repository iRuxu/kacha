# 咔嚓旧版 OSS 项目同步设计

旧版工作台通过云朵按钮打开同步弹窗，供用户在多台电脑间下载项目、更新文件和增量上传。该入口目前已停用。下文保留旧版实现细节，现行媒体存储配置见[咔嚓 README 的 Git LFS 存储设置](../README.md#git-lfs-存储设置)。

## 项目文件和设备状态

- `config/oss-sync.json` 是可以随项目流转的同步基线，包含项目 ID、已应用的版本号、各文件的相对路径、大小和 SHA-256。文件应保留在项目目录中，并作为同步元数据单独传输，避免把清单本身纳入文件指纹计算。
- OSS 在配置的路径下存放不可变的版本清单和文件对象。每份清单记录父版本及每个路径对应的文件指纹和对象键。文件对象按内容指纹定位，相同内容可在多个版本间复用。
- `.kacha/oss-sync/` 保存当前设备的分片检查点、下载临时文件和进行中的任务状态。`.env` 保存各电脑自己的 OSS 访问凭据。两者都继续留在本机。

## 下载已有项目

命令行可在空目录内执行 `kacha clone .`，也可从其它目录执行 `kacha clone <目标目录>`。省略目标目录时使用当前目录。先在目标目录写入本地 `.env`，填入同一个 OSS 地址、Bucket、路径和自己的 AccessKey。下载校验通过后，咔嚓会写入 `config/oss-sync.json`。下载中断时，重跑命令会跳过已校验且仍与云端一致的文件。目标目录里发现冲突或多余的文件时，请换空目录或先移走冲突文件。

新电脑配置同一个 OSS 项目路径后，选择「下载项目」。工作台先读取最新版本清单，展示将下载的文件和大小。文件流式写入暂存路径，校验 SHA-256 后再写入本地。遇到目标路径已有且内容不同的文件时，列入冲突待处理。成功应用整个版本后，将对应基线写入本地的 `config/oss-sync.json`。

已有远端版本且本地缺少基线时，先执行下载或导入比对。只有项目尚未在 OSS 建立版本，并且用户确认初始化时，才全量上传。

## 上传改动与处理冲突

每次打开同步弹窗先做三方比对：本地基线、本地文件、OSS 最新版本。确认前展示目标版本和将处理的文件，实际执行前再核对远端版本和相关本地文件。

| 文件变化 | 处理方式 |
| --- | --- |
| 两端与基线一致 | 跳过 |
| 只有本地改动 | 纳入本次上传 |
| 只有 OSS 改动 | 纳入本次下载 |
| 两端改动后内容一致 | 采用相同结果 |
| 两端改动后内容不同 | 保留双方，显示冲突，等待选择 |
| 一端删除或改名 | 列入预览，明确确认后处理，原对象保留在历史版本 |

如果 OSS 有更新，先应用可安全下载的文件，再上传自己的改动。不同路径的改动可以同时保留。同一路径发生冲突时，保留本地文件，远端版本可暂存供查看。下载期间重新检查目标文件，避免覆盖刚修改的内容。整批更新核验通过后才推进本地基线。只完成一部分时，重试会跳过已核验的文件；未完成的单个下载会重新读取。

## 并发发布

先上传不可变的文件对象和新版本清单，全部成功后才发布版本。使用 OSS `AppendObject` 按预览时读到的字节偏移追加版本记录。另一台电脑先发布时，OSS 返回 409，本次保留已传对象，重新生成比对结果。普通 `PutObject` 的 `If-Match` 无法实现这个步骤。响应丢失时，按版本 ID 查发布日志确认结果，避免重复发布。[阿里云 AppendObject](https://www.alibabacloud.com/help/en/oss/developer-reference/appendobject) · [PutObject 条件请求限制](https://www.alibabacloud.com/help/en/oss/user-guide/0017-00000245)

## 迁移已有的平铺备份

旧版 OSS 文件按项目路径平铺。「迁移并发布」以当前完整项目为准生成初始版本。预览显示旧对象数及同路径、同大小的候选数。确认后，逐个读取候选对象校验 SHA-256，吻合时在 OSS 内按源 ETag 条件复制，其余本地文件上传。只有旧备份里存在的对象仍保留原路径，可按需从旧备份取回。生成初始清单并成功发布后，再写入项目基线。[阿里云 HeadObject](https://www.alibabacloud.com/help/en/oss/developer-reference/headobject) · [阿里云 CopyObject](https://www.alibabacloud.com/help/en/oss/developer-reference/copyobject)
